Import multiple XML files into a Moodle question bank

Moodle's import screen takes one file at a time. When a course arrives as several exported banks — per topic, per author, per legacy course — the naive loop loses categories, collides ids and silently drops embedded files. Here is the reliable path, and how to prove the result.

What Moodle XML actually carries

A Moodle XML export is a <quiz> element containing <question> elements. Two details matter when merging:

  • Categories are questions too. A <question type="category"> element sets the category for the questions that follow it, via a path like $course$/top/Topic 1. If you concatenate files without re-emitting category markers, later questions land in the wrong category — or the default one.
  • Embedded files are references. Images and media appear as @@PLUGINFILE@@ URLs with base64 <file> elements. A merge that strips or re-encodes them breaks the question on import.

The manual path (and where it fails)

  1. In the source course, export each bank: Question bank → Export → Moodle XML format, one category at a time.
  2. In the target course, import each file: Question bank → Import → Moodle XML format. Tick "Get category from file" if you want the export's category path honored; otherwise pick the category explicitly.
  3. Repeat per file. After each import, check the count shown against the source.

Failure modes we see in practice: two files use the same question name (Moodle treats names as identifiers within a category, so the second can overwrite or duplicate); a file exported from an older Moodle carries category paths that no longer exist in the target; cloze subquestions are miscounted because they share the parent's name in some queries; embedded files import but render broken because the reference was rewritten.

The merged-file path

Instead of N imports, build one import file that re-emits a category marker whenever the category changes, preserves each question element byte-for-byte, and rejects duplicate (category, id) pairs before you ever touch Moodle:

<?xml version="1.0" encoding="UTF-8"?>
<quiz>
  <question type="category"><category><text>$course$/top/Topic 1</text></category></question>
  ...questions from bank A, unchanged...
  <question type="category"><category><text>$course$/top/Topic 2</text></category></question>
  ...questions from bank B, unchanged...
</quiz>

Then import once, with "Get category from file" enabled. One import, one count to check, categories intact.

Prove it with a receipt

Before importing, produce a row per question: source file, category, id, source line, SHA-256 of the question element. After importing, export the target bank and compare counts per category and a sample of checksums. If a row is missing or changed, you know exactly which source line to re-open — not "something went wrong with 300 questions".
