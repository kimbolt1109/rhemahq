Guide · Moodle

Verify a Moodle question import, line by line

"Import successful" is not evidence. Moodle can report success while a category collapsed, a duplicate name overwrote a question, or an embedded file broke. This is a spot-check procedure you can run in ten minutes, and the receipt that makes it mechanical.

What silently goes wrong

  • Category drift. Without "Get category from file", everything lands in the chosen category; with it, a stale path can create an unexpected one.
  • Name collisions. Question names act as identifiers within a category. Two banks using "Q1" collide.
  • Cloze undercount. Cloze subquestions can share the parent name in indexed queries; a naive count reports shortanswer children as separate questions or misses them.
  • Embedded files. Base64 <file> payloads must survive byte-for-byte; a rewritten @@PLUGINFILE@@ reference renders broken.
  • Settings loss. Default marks, penalties, shuffle flags and answer fractions are easy to drop in a hand-rolled conversion.

The ten-minute spot-check

  1. Count per category, not total. Export the target bank (Moodle XML) and count top-level questions per category. Compare against the source counts. Totals can match while two categories swapped contents.
  2. Check top-level vs children. Count cloze parents separately from their subquestions; verify each parent's child count and answer settings.
  3. Sample five questions across types (multichoice with multiple correct, truefalse, shortanswer case sensitivity, numerical tolerance, essay attachment config). Open each in the preview and confirm grading settings.
  4. Hash the embedded files. Extract each <file> payload from source and target exports and compare SHA-256. Equal hashes mean the bytes survived.
  5. Test permissions. Confirm an editing teacher can import and re-export, and a student cannot import — the capability check, not just the happy path.

Make it a receipt instead of a ritual

A receipt row per question — source file, category, id, type, source line, SHA-256 of the question element — turns the spot-check into a diff. Re-run the export after import, recompute hashes, and any mismatch points at an exact source line. Keep the receipt with the release record so an auditor can re-open what was read.

Limits
